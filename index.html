Video Memory (VRAM) Framebuffer Architecture

In modern computer graphics displays (CRT, LCD, OLED), each raster pixel is mapped directly to consecutive bytes in the video controller's frame buffer memory:

Byte 0 [R] 25
Byte 1 [G] 63
Byte 2 [B] EB
Byte 3 [A] FF (255)
  • Color Depth: 24-bit TrueColor generates \(2^{24} = 16,777,216\) distinct colors.
  • Screen Resolution Calculation: A 1920×1080 display requires:
    1920 × 1080 × 4 bytes = 8,294,400 bytes ≈ 7.91 MB VRAM per frame.
  • DOM Rendering Engine: CSS color parsing internally converts Hex/HSL into 32-bit RGBA integer values before GPU rasterization.

Laboratory Mini-Project Academic Documentation

Subject: Object Oriented Programming and Computer Graphics (OOPSCG) | Course Code: 210243 / 210250

1. Abstract

The Library Management System (LMS) is an interactive, enterprise-grade web application developed as an academic mini-project for Second Year Computer Engineering students. The system eliminates manual library paper registries by automating cataloging, student enrolment, book circulation (issues and returns), and late fee computation. The system demonstrates rigorous Object-Oriented Programming (OOP) paradigms implemented natively in JavaScript (ES6+), coupled with an educational Computer Graphics (CG) module connecting real-world UI graphics with core curriculum algorithms like 2D transformations, homogeneous coordinates, and raster scan mechanics.

2. Introduction & University Curriculum Context

In the Computer Engineering Syllabus, the course Object Oriented Programming & Computer Graphics (OOPSCG) bridges algorithmic software design with visual computational geometry. This project serves as an end-to-end practical realization of these dual pillars: utilizing OOP design patterns for reliable, maintainable business logic while demonstrating how graphical screen rendering operates at the mathematical and pixel levels.

3. Problem Statement

Conventional college libraries face issues including misplaced books, lack of real-time availability tracking, inaccurate calculation of overdue penalties, and cumbersome paper ledgers. The goal is to engineer a responsive, client-side, zero-server-dependency Library Management System that persists state seamlessly using Web LocalStorage while illustrating robust OOP architecture and computer graphics principles.

4. Objectives

  • To architect a modern, responsive web dashboard with clean blue-and-white university aesthetics.
  • To implement full CRUD operations (Create, Read, Update, Delete) for Books and Students with real-time validation.
  • To automate book circulation with automated inventory decrements/increments and overdue late fine evaluation.
  • To demonstrate core OOP principles: Classes, Objects, Constructors, Encapsulation, Inheritance, Polymorphism, and Abstraction.
  • To provide interactive Computer Graphics experiments mapping theoretical 2D transformations and DDA rasterization directly to browser canvas graphics.
  • To implement persistent data storage using browser LocalStorage with automatic fallback and sample seeding.

5. System Scope

The application encompasses library administration within an academic department: catalog maintenance, student member registration, active issue tracking, fine receipts, tabular search/filtering, printable university-format reports, and an educational graphics laboratory. It is entirely portable, needing no backend servers, databases, or npm dependencies.

8. OOP Concepts Demonstrated in Code

Classes & Objects

ES6 class syntax encapsulates data and functions into cohesive instances (e.g. creating new Book(...) and new Student(...)).

Encapsulation

Internal object states are stored in protected/private fields (prefixed with _) with controlled accessors (getters) and mutating methods enforcing state validation (e.g. preventing negative copy counts).

Inheritance

Code reuse through parent-child relationships: Book extends LibraryItem, and Student extends Person using the extends and super() keywords.

Polymorphism

Subclasses override base class methods like getDetails() and getRole() to supply specialized implementations tailored to Books and Students while sharing a common interface.

Abstraction

Complex business rules (such as inventory adjustments, overdue fine algorithms, and LocalStorage JSON serialization) are hidden behind intuitive public methods like library.issueBook() and library.returnBook().

9. Connection to Computer Graphics (OOPSCG)

The user interface inherently relies upon foundational computer graphics concepts taught in the Computer Graphics syllabus:

  • 2D Screen Coordinate System: Unlike standard Cartesian coordinates where origin (0,0) is at the center or bottom-left, display monitors and HTML5 Canvas locate (0,0) at the top-left, where \(X\) increases to the right and \(Y\) increases downwards.
  • Homogeneous Coordinates & 3×3 Matrices: All affine transformations (Translation, Scaling, Rotation, Shearing) are represented using \(3 \times 3\) matrices, allowing complex multi-step transformations to be concatenated through matrix multiplication:
    P' = P × M_composite.
  • Rasterization & DDA Algorithm: Digital Differential Analyzer evaluates intermediate pixel values using line differential steps \(\Delta x\) and \(\Delta y\), illustrating how software algorithms bridge mathematical vectors into discrete screen pixels.
  • Color Depth in VRAM: The blue-and-white theme is rendered through 24-bit TrueColor RGBA memory buffers inside the graphics pipeline.

10. Advantages

  • Zero Backend Setup: Runs out-of-the-box on any browser with zero installation, npm packages, or server configuration.
  • Data Persistence: State persists across page refreshes and browser restarts via HTML5 LocalStorage.
  • Academic Alignment: Directly addresses Second Year Computer Engineering viva questions and syllabus requirements.
  • Print-Ready Reporting: Formatted print stylesheets allow instant generation of official department reports with signature blocks.

11. Limitations

  • Browser LocalStorage is domain-bound and typically limited to ~5MB of JSON data.
  • Multi-user concurrency across different physical computers requires a central backend/cloud database.
  • Does not feature physical hardware barcode/RFID scanner drivers directly.

The Central Library Management System successfully implements a robust, maintainable, and visually polished software application. 14. Viva Voce Preparation Guide (Sample Questions & Answers)

Q1: Why did you use classes in JavaScript if it's a prototype-based language?

Answer: ES6 introduced syntactic sugar for classes over prototype inheritance. This provides clearer encapsulation, constructor syntax, inheritance via extends and super(), making code modular, maintainable, and aligned with standard OOP design.

Q2: How is Polymorphism demonstrated in your project?

Answer: Both Book and Student inherit from base classes (LibraryItem and Person). They override methods such as getDetails() and getRole(). When invoked on any entity, JavaScript executes the subclass's specific implementation at runtime.

Q3: How does LocalStorage store objects?

Answer: LocalStorage only accepts string key-value pairs. We use JSON.stringify() to serialize our objects before saving, and JSON.parse() combined with static factory methods (e.g. Book.fromJSON()) to rehydrate class instances upon page load.

Q4: How does the Computer Graphics transformation matrix work in 2D?

Answer: A 2D point \((x, y)\) is expressed in homogeneous coordinates as \([x, y, 1]\). We multiply this vector with a \(3 \times 3\) transformation matrix combining Translation, Rotation, and Scaling into a single composite matrix.
